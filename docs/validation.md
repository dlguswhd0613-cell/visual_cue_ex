# 현재 검증 결과

실제 장치 없이 클라우드에서 수행한 결과입니다.

## Python에서 세션 최대 1시간 및 ITI 터미널 표시

- Python 자동 검사 64개, 실제 스케치를 사용하는 호스트 C++ 가상 검사 27개 묶음 통과.
- Arduino 스케치·가상 보드·펌웨어 검사는 1시간 제한 추가 전의 보상 후 lick 종료 버전(`771cc24`)으로 복원했습니다. Python이 기존 `STOP`만 사용하며 `SESSION_LIMIT_CAPS`를 보내지 않는지 검사했습니다.
- 호스트의 3600초 경계, 화면·디스크 작업보다 먼저 STOP 전송, 회색 복귀, 미완료 trial 제외, 정지 전 이미 완료된 trial 집계, 전송 중이던 cue 요청에 ACK를 보내지 않는지 확인했습니다. 정지 응답이 없거나 다른 중단 사유가 있으면 정상 완료로 기록하지 않습니다.
- 이전 펌웨어를 모사한 가상 보드와 화면 없는 GUI로 Python 준비·자동 시작·시간 제한·STOP 확인·종료 코드 0·기록 저장까지 검사했습니다. 실제 한 시간을 기다리지 않고 호스트 시계 또는 제한 시간을 대체해 검증했습니다. 100회 조기 완료와 수동 중단도 검사했습니다. TTL 단독 시험과 priming에는 이 제한을 적용하지 않습니다.
- ITI 시작은 `ITI_START`, 대기 시간은 `ITI_DURATION_S`로 터미널에 즉시 표시됩니다.
- 실제 Uno 업로드·AVR 타깃 컴파일·Pi와 실물 장비의 한 시간 측정은 수행하지 않았습니다. 아래는 이전 버전의 검증 기록입니다.

## 보상 후 lick으로 시행 종료

- Python 자동 검사 56개, 실제 스케치를 사용하는 호스트 C++ 가상 검사 27개 묶음 통과.
- 보상 전 lick·유지된 HIGH·50ms 미만 중복 감지는 종료 조건에서 제외하고, 보상 후 첫 유효 lick으로 종료되는지 확인했습니다. 밸브 개방 중 lick이 30ms 펄스를 줄이지 않는지, lick 없이 60초 기다려도 다음 ITI로 넘어가지 않는지, 마지막 시행도 lick을 요구하는지 검사했습니다.
- ITI 시작 시각이 실제 trial 종료 시각과 같으며, 다음 시행에서 이전 lick이 재사용되지 않는지 확인했습니다. 100회 시행 모두 보상 후 lick을 제공한 전체 세션도 검사했습니다.
- 대기 중 STOP·통신 끊김·millis 오버플로, 비보상 시행의 고정 관찰 시간, 기존 TTL·priming 기능을 검사했습니다. 기존 고정 종료 펌웨어는 Python 준비 단계에서 거부합니다.
- 실제 Uno 업로드, AVR 타깃 컴파일 및 센서 실측은 수행하지 않았습니다. 아래 내용은 이전 동작의 검증 기록입니다.

## pyPhotometry 트리거 추가 검증

### D7 단독 시험 추가

- Python 자동 검사 53개 통과. TTL 전용 CLI의 펄스 완료 응답, 구버전 펌웨어 거부, 잘못된 폭 거부, heartbeat와 응답 시간 초과, TTL 명령만 전송하는지 및 Ctrl+C 정리를 포함합니다.
- 실제 스케치를 사용하는 호스트 C++ 가상 검사 24개 묶음 통과. 단독 D7 펄스 폭 1/20/100/1000ms, 밸브·D9·LED·부저 LOW 유지, STOP, 호스트 끊김 후 자동 LOW, millis 오버플로, 잘못된 입력 및 다른 모드와의 상호 배제를 검사했습니다.
- 실제 Uno 업로드, AVR 타깃 컴파일, 전압 측정 및 pyPhotometry 수신 검증은 이번 환경에서 수행하지 않았습니다.

### 앞선 트리거 검증

- Python 자동 검사 47개 통과. 기본 트리거 설정, 범위 검사, 이전 설정 파일 호환, 공통 출력 이벤트 기록, 비보상 시행 및 중단 시 신호 취소를 포함합니다.
- 실제 Arduino 소스를 사용하는 C++ 가상 입출력 검사 21개 묶음 통과. 공통 D7이 cue와 reward 각각 100ms 전에 20ms 펄스를 출력하며, 다음 시행에서 다시 출력되는지 확인했습니다. STOP·watchdog·프로토콜 오류에서 LOW 복귀, 비보상/수동 밸브 조건, 잘못된 설정, 예정 시각까지 트리거를 보내지 못한 경우 중단, millis 오버플로, 시행 종료에서 긴 펄스 잘림, 공유 핀의 펄스 겹침 거부도 검사했습니다.
- 이번 변경은 호스트 C++로 검증했습니다. 이번 버전의 AVR 타깃 컴파일, 실제 Uno 업로드 및 pyPhotometry BNC 입력 측정은 수행하지 않았습니다. 아래 메모리 수치는 이전 버전의 기록입니다.

## 이전 버전 검증 기록

- Python 자동 검사 36개 통과: Gabor 주파수·방향·배경, 설정·시행표, 데이터 기록, 모의 통신·중단 동작, 수동 밸브 명령과 연결 확인. 실제 장치용 CLI의 자동 시작 및 Ctrl+C 중단 경로도 모의 직렬 장치와 가상 화면으로 검사했습니다. Pi에서 SSH 화면 표시는 실제 환경에서 확인해야 합니다.
- 실제 Arduino 소스를 사용하는 C++ 가상 입출력 검사 14개 묶음 통과. 전체 100회, lick이 없는 조건, 타이머 오버플로, 통신 끊김, 늦은 자극 확인, 밸브 개방 중 정지, 수동 계속 열기/반복 여닫기 및 실험 모드와의 상호 배제를 포함합니다.
- Uno용 컴파일 성공: flash 6,578 / 32,256 bytes, SRAM 전역 변수 849 / 2,048 bytes. Arduino CLI 1.5.1, Arduino AVR Boards 1.8.8.
- Pygame의 화면 없는 드라이버로 화면·CSV를 포함한 3회 모의 세션을 완료했습니다. 자극 실제 소프트웨어 표시 간격은 2,000–2,004ms였습니다. 이후 자극 시작 확인의 허용 지연을 100ms로 강화하고 1회 모의 세션을 재실행해 정상 종료를 확인했습니다.
- 최종 모의 기록에서 시행 시작 기준 보상 9,000ms, 시행 종료 13,000ms를 확인했습니다. 전체 100회 스케치 검사에서는 총 4,660초(77분 40초)에 종료했습니다. 시작 신호 3초 + 최초 대기 90초 + 100 × 13초 + 99 × 33초입니다.

위 결과는 실제 모니터의 발광 시점이나 밸브의 유량 측정 결과가 아닙니다. Pi 4B 화면, USB 통신, lick 센서, 밸브 및 외부 기록 장비의 연결은 실제 장치에서 확인해야 합니다. 화면의 `DISPLAY_ON`/`DISPLAY_OFF`는 소프트웨어 화면 갱신 반환 시각이고, Uno TTL은 USB로 전달된 화면 확인 메시지의 수신 시각입니다.

재검사 명령은 README에 있으며, 원본 연구실 파일은 `reference/`에 보관했습니다. 원본 스케치와 새 Pi 프로그램은 통신 규약이 달라 함께 사용할 수 없습니다.
